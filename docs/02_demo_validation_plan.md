### 2.1 使用前必须核验

- 仅将候选样本用于解析 API 和字段支持的技术验证，不先将其认定为论文最终实验数据。
- 下载后核验文件大小、SHA-256、地图、模式、队伍人数、回合数和事件字段。
- 必须在报告中记录样本来源、固定提交和校验值。
- 必须在用户明确同意后才可将候选样本用于项目演示或论文实验。
- 若公开样本不能确认常规 5v5 模式，则只用于解析回归测试，不作为项目主样本。

## 3. 验证步骤

### 3.1 基础文件检查

1. 下载候选 Demo 至 `data/demo/`。
2. 校验 SHA-256。
3. 确认文件扩展名、大小和能否被解析库打开。
4. 将 Demo 文件加入 `.gitignore`，避免个人标识和大文件进入 Git 仓库。

### 3.2 元数据与玩家检查

运行：

```powershell
.\.venv\Scripts\python.exe scripts\inspect_demo.py data\demo\<sample>.dem --output data\interim\inspection.json
```

检查：

- 地图名称。
- 可解析玩家数量、阵营和 Steam ID 字段。
- 是否包含常规 5v5 所需的 10 名玩家。
- 是否能识别竞技/Premier 模式，或只能通过规则事件推断。

### 3.3 事件字段检查

至少验证以下事件能够查询：

- `round_start`
- `round_end`
- `player_death`
- `player_hurt`
- `bomb_planted`
- `bomb_defused`
- `bomb_exploded`
- 手雷投掷和爆炸事件

同时记录每个事件可用字段、缺失值、时间字段和回合字段。

### 3.4 位置与经济检查

- 能否按固定采样频率取得全部玩家位置。
- 位置坐标含义和地图坐标系是否一致。
- 能否取得现金、装备价值、存活状态、生命值和队伍信息。
- 能否按回合边界截取数据。
- 解析同一文件多次是否得到一致结果。

### 3.5 解析性能检查

记录：

- 文件大小。
- 头部/玩家解析耗时。
- 位置抽样耗时。
- 全部关键事件解析耗时。
- 峰值内存（若可稳定测量）。

单场分析应在可接受的本地演示时间内完成，具体阈值待真实样本测试后确定。

## 4. 解析库比较条件

Awpy 与 demoparser2 的最终取舍不能只依据文档。应使用同一 Demo 比较：

| 维度 | 评价内容 |
|---|---|
| 安装稳定性 | Windows、Python 3.13 下能否稳定安装 |
| 字段覆盖 | 玩家、回合、击杀、伤害、道具、包点、经济、位置 |
| 坐标一致性 | 是否能与地图雷达图坐标对齐 |
| 解析速度 | 同一 Demo 的总耗时和内存 |
| 数据接口 | 是否便于输出结构化事件和指标 |
| 可解释性 | 字段名、原始事件和派生逻辑是否可追溯 |
| 维护状态 | 版本、更新、文档和社区活跃度 |

只有在真实 Demo 上完成相同检查后，才确定主解析库。另一个库可作为交叉验证工具。

## 5. 当前停止条件

出现以下任一情况时，不继续以该样本开发分析功能：

- 不是常规 5v5 对局。
- 无法获得稳定的回合、玩家或关键事件数据。
- 位置或经济字段大量缺失，无法支撑报告要求。
- Demo 来源或使用授权不满足学校要求。
- 文件损坏或解析结果不可重复。
