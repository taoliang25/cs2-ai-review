# 当前进度与需求确认

- 更新时间：2026-11-04
- 当前定位：开题阶段、可运行本地原型
- 最新确认：导师没有强制要求独立的机器学习算法创新
- 用户核心诉求：让 AI 根据玩家 Demo 生成表现总结和具体改进建议

## 1. 已确认的技术重心

系统不为了“算法创新”强行加入分类器、聚类或 LightGBM。当前主路线固定为：

```text
真实 Demo
  -> 解析击杀、伤害、位置、道具、经济、目标和回合事件
  -> 计算可解释行为指标
  -> 识别可解释行为模式
  -> 选出优秀回合和问题复盘回合
  -> 结构化事实包
  -> 大模型生成建议总结
  -> 证据校验；失败则回退模板报告
```

需要特别说明：当前系统不是直接把整段游戏视频交给视觉大模型。它读取 `.dem`
中的完整事件与位置数据，再把结构化对局事实交给语言模型分析。对于“路线、交战、
道具、经济和回合决策”这个目标，事件数据比视频更准确，也更容易证明没有编造。

### 1.1 用户已经确认的选择

1. AI 分析 Demo 中的位置与事件数据，不额外接入整段视频视觉模型。
2. 最初选择云端与本机模型双路线；后续考虑到答辩期间可持续联网，
   最终决定从 MVP 移除本机大模型，保留本地模板故障兜底。
3. 用户已有 DeepSeek API；密钥不通过聊天发送。
4. 最终同时准备公开完整赛事 Demo 和用户自己的 Demo；任意新 `.dem` 都应能上传解析。
5. AI 建议采用温和、具体的教练式语气。
6. 报告需要 Markdown、Word 和 PDF。
7. 用户需要详细指导，尤其是队友在具体位置阵亡后，玩家应去哪里、做什么。
8. 答辩可以使用手机热点，不要求全离线，但仍保留本地模板兜底。
9. 截止日期暂时未知；用户每天可投入 3–5 小时。
10. 允许本机处理 Demo；允许将去标识化统计与事件摘要发送给云端 API。

### 2.3 玩家分析

目前实现 19 项整场指标，包括：

- 开局活动和首次离开出生区地点。
- 常用路线和活动区域。
- 最近队友距离、近队和远端比例。
- 首轮交火参与、首杀和首死。
- 队友接敌时的距离与 5 秒内响应。

- 最后存活残局。
- 道具购买和可观测道具效果。

单回合已能生成：

- 发生了什么。
- 什么时候、在哪里发生了关键动作。
- 对人数、目标或回合结果有什么可观察影响。
- 当时可考虑的其他选择。
- 支持这些描述的证据 ID。

## 4. 建议的后续路线

### 阶段 A：确认 AI 使用方式

根据用户选择，接通云端 API 或本地模型。完成一次真实报告，检查质量、延迟、成本和隐私。

### 阶段 B：优化“像教练一样提建议”

用 3–5 个完整赛事案例和用户自己的 Demo 调整报告：

- 少讲空泛原则。
- 多引用具体时间和位置。
- 区分事实、行为推断和训练建议。
- 指出哪些建议可执行、下一场如何验证。

### 阶段 C：人工评价与系统修正

逐条检查：

- 系统描述是否与 Demo 事件一致。

- 替代方案是否与当时信息相符。
- 训练建议是否明确、不过度。

记录模板与真实大模型在事实一致性、可读性和建议具体程度上的差异。
