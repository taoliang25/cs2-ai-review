## 1. 暂定题目

**基于对局事件的《CS2》战术识别与赛后智能复盘系统设计与实现**

可考虑但尚未最终确定的备选题目：

- 面向单场 Demo 的《CS2》行为分析与智能复盘系统。
- 基于事件证据的《CS2》玩家决策复盘系统设计与实现。

导师已明确不强制要求独立的机器学习算法创新。题目仍应兼顾系统实现、应用价值和可解释性。

## 2. 研究背景

《CS2》的赛后统计通常侧重击杀、死亡、伤害和评分，能够回答“结果是什么”，但较难解释：

- 玩家开局选择去了哪里。
- 玩家是否与队伍保持协同。
- 关键道具是否服务于团队行动。
- 自由交火、支援和残局选择对局势产生了什么影响。
- 同样的问题为什么会在不同局势下反复出现。

Demo 记录了位置、事件、经济、武器和目标状态，但这些原始数据不天然构成“战术解释”。大模型可以改善表达，却可能在缺少约束时编造比赛过程。因此，本研究拟建立“真实事件指标—关键回合识别—证据约束报告”的分析链路。

## 3. 核心问题

本研究拟回答三个问题：

1. 如何从单场常规 5v5 Demo 中提取能够解释个人行为倾向的事件和轨迹特征？
2. 如何结合事件影响、比分经济状态和行为稳定性，找出值得复盘的正反面回合？
3. 如何让智能报告只解释真实事实、引用可核验证据，并在无大模型 API 时仍可运行？

## 4. 研究目标

构建一个本地网页原型，完成：

- 上传一场 CS2 常规 5v5 Demo。
- 从真实玩家列表中选择一个主要分析对象。
- 生成该玩家的打法画像、回合时间线、关键决策、单回合复盘和训练建议。
- 展示位置图、热力图、经济变化和事件证据。
- 支持大模型报告与模板报告降级。
- 对关键指标、划分方式和模型局限给出可复现说明。

## 5. 研究内容

### 5.1 数据解析与结构化

- 使用 Awpy 解析回合、玩家、击杀、伤害、炸弹、投掷物、经济、位置和地点名称。
- 使用 demoparser2 交叉校验关键事件。
- 将事实数据规范化保存到 SQLite。
- 处理赛后事件、阵营切换、观战者过滤和字段缺失。

### 5.2 行为特征计算

- 开局路线和区域偏好。
- 跟队、分离与队友距离。
- 首轮交火、首杀和首死。
- 优势局、均势局和劣势局中的行为差异。
- 道具购买、可观测效果与使用场景。
- 支援距离、到达与交战参与。
- 残局最后存活状态和结果。

### 5.3 战术模式与关键回合

首版采用可解释规则识别“抢区、默认控图、独立潜伏、跟随主攻、优势压迫、劣势回防、残局等待/主动找信息”等模式。

关键回合同时考虑：

- 优秀表现。
- 问题复盘候选。
- 对人数、经济、目标或比分走势的影响。
- 对个人行为倾向的代表性。

### 5.4 证据约束的智能复盘

- 先生成结构化事实包。
- 大模型只能使用事实包中的指标和事件。
- 输出必须引用证据 ID。
- 增加事实一致性校验。
- 无 API 时使用确定性模板报告。

## 6. 技术路线

```text
CS2 Demo
  -> Awpy 解析
  -> 事实归一化与 SQLite
  -> 行为特征与规则识别
  -> 关键回合排序
  -> FactBundle
  -> 模板报告 / 可替换大模型
  -> Streamlit 网页展示
```

当前验证环境：

- Python 3.13。
- Awpy 3.1.1。
- demoparser2 0.42.1。
- Polars / Pandas。
- SQLite。
- Streamlit。
- Plotly。

导师未强制要求机器学习算法创新，因此首版以可解释事件规则和证据约束大模型为核心，不预先加入 LightGBM、SHAP 或分类器。

## 7. 当前可展示成果

- 已用真实公开测试 Demo 跑通解析。
- 已形成数据库与事实层。
- 已计算首批真实行为指标和证据编号。
- 已生成六部分模板复盘报告。
- 已形成 Streamlit 网页主流程和 Mirage 位置热力图。
- 自动化测试覆盖真实导入、10 名玩家分析、证据引用和网页主流程。

这些结果证明工程链路具备可行性，不代表战术识别准确率已经得到验证。

## 8. 拟议技术贡献

原始版本中不要把这些直接写成“重大算法创新”。可先表述为设计特色或预期贡献：

1. 面向单场对局的“事件事实—行为指标—关键回合—证据约束报告”分层链路。
2. 同时覆盖个人行为倾向与回合局势影响的复盘方式。
3. 对生成内容进行证据 ID 和事实边界校验，并提供无大模型降级路径。
4. 将轨迹、事件和经济证据与自然语言建议对齐，避免只给出比赛评分。

若后续采用聚类、异常检测或有监督识别，需要补充：

- 数据集规模和标签来源。
- 算法选择和基线。
- 按 Demo 分组的数据划分。
- 防止未来信息泄漏。
- 稳定性和泛化实验。
- 与可解释规则基线的比较。

只有真实实验支持时，才能将相应算法写入“创新点”。

## 9. 实验设计草案

### 9.1 解析有效性

- 多个 Demo 的成功解析率。
- 玩家、回合、击杀、伤害和炸弹事件覆盖率。
- Awpy 与 demoparser2 的交叉一致率。
- 区域名称和雷达坐标抽查。

### 9.2 特征与规则一致性

- 同一选手重复计算结果稳定性。
- 不同采样间隔对跟队距离和支援判断的敏感性。
- 规则阈值变化对关键回合排序的影响。
- 人工抽查若干回合是否支持系统描述。

### 9.3 报告真实性

- 报告中证据 ID 有效率。
- 无依据事件、比分或回合描述数量。
- 事实、推断和建议是否明确区分。
- 模板报告与 API 报告在事实一致性、可读性上的对比。

### 9.4 若使用机器学习

- 必须按 Demo 分组划分训练、验证和测试集。
- 报告类别不平衡、标签一致性和基线。
- 不得用同一条规则既生成标签又独立验证模型准确率。
- 推荐补充消融实验，但以真实数据和导师要求为准。

## 10. 当前风险

| 风险 | 对开题的影响 | 应对 |
|---|---|---|
| 只有一个公开测试 Demo | 无法验证泛化 | 继续收集合规、完整的常规 5v5 Demo |
| 行为标签缺少真值 | 难以证明分类准确率 | 先做可解释规则，必要时人工标注并报告一致性 |
| 大模型可能编造 | 影响可信度 | 事实包、证据校验、模板降级 |
| 导师未要求独立机器学习创新 | 技术重点应放在完整闭环和可解释性 | 保留规则分析基线，不为了形式增加复杂模型 |
| 学校模板与截止时间未定 | 无法最终确定论文结构 | 模板和任务书下发后统一适配 |
