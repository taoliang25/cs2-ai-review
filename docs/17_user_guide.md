# 本地系统使用说明

## 1. 启动

在项目目录打开 PowerShell：

```powershell
cd D:\毕业设计
.\run_app.ps1
```

浏览器访问：

`http://localhost:8501`

如果提示端口已占用，说明页面可能已启动，可直接打开上述地址。

答辩期间需要让其他电脑访问时：

```powershell
.\start_public_demo.ps1
```

终端会打印一个临时 HTTPS 网址和访问口令提示。保持电脑开机、联网且不休眠。
演示结束后运行：

```powershell
.\stop_public_demo.ps1
```

## 2. 使用已有测试 Demo

1. 在“已缓存验证 Demo”下拉框中选择文件。
2. 推荐选择 `furia-vs-falcons-m2-nuke.dem`：42 回合的完整赛事样本。
3. 点击“载入已缓存的测试 Demo”。
4. 从解析出的 10 名玩家中选择一人。
5. 点击“生成本场画像与复盘”。
6. 在五个标签页中查看总览、位置路线、关键回合、单回合和报告。

## 3. 上传自己的 Demo

1. 在 `data/demo/` 或游戏安装目录找到 `.dem`。
2. 在网页上传框选择文件。
3. 点击“解析这场 Demo”。
4. 首轮解析会建立 SQLite 事实库；同一文件再次使用会直接复用。

上传上限为 1 GB。大文件采用分块写盘，但首次解析仍可能需要几十秒。

## 4. 页面结构

- 全场总览：核心指标、活动区域、回合时间线和队伍经济。
- 位置与路线：全场或单回合雷达图、路线和位置热力图。
- 关键回合：优秀表现、高影响和优先复盘候选。
- 单回合复盘：事件时间线、可观察影响、战术模式和备选方案。
- 智能复盘报告：六部分模板报告，可下载 Markdown。

## 5. 报告引擎与导出

网页默认使用本地模板，不需要 API。

网页侧边栏可选择：

- 本地模板：无需网络。
- DeepSeek 云端：配置 `DEEPSEEK_API_KEY` 后使用。

具体配置见
`docs/10_ai_reporting_and_validation.md`。

最简单的配置方式是把 `.env.example` 复制为 `.env`，只在本机填写
`DEEPSEEK_API_KEY`。`.env` 已被 Git 忽略，不要把密钥发到聊天或提交仓库。

外部模型只接收去标识化事实和事件摘要。模型输出未通过证据校验时，系统会自动改用模板。

报告完成后可下载 Markdown、Word 和 PDF。当前文件采用通用排版；学校模板下发后，再适配封面、页眉、字体和章节编号。

## 6. 常见提示

- “未检测到完整比赛结束”：文件可能是录制片段。
- “未达到常规赛目标得分”：可能是投降、提前结束或非常规模式。
- “当前位置没有地图雷达资源”：需要补充对应地图缓存。
- “大模型报告未采用”：API、网络或输出校验失败，模板报告仍可使用。

## 7. 数据安全

- Demo、SQLite、地图缓存和报告输出默认只存本地。
- 原始 Demo 与数据库已被 `.gitignore` 排除。
- 不要将个人 Demo、Steam ID 或 API 密钥提交到公开仓库。
