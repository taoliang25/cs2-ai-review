## 1. 数据获取与预处理

### 1.1 输入与范围

系统输入为单场《CS2》常规 5v5 Demo。首版支持竞技或 Premier 等常规对局，不处理死亡竞赛、军备竞赛和 Wingman。Demo 解析后需要保留回合、玩家阵营、击杀、伤害、投掷物、炸弹、经济、位置和地图地点信息。

### 1.2 解析器选择

系统以 Awpy 3.1.1 为主解析器，demoparser2 0.42.1 用于关键事件交叉校验。选择 Awpy 的原因是：

- 能同时提供回合、玩家、击杀、伤害、炸弹、投掷物、经济、射击和位置快照。
- 能查询 `m_szLastPlaceName`，获得真实地图地点名称。
- 当前 Windows 与 Python 3.13 环境安装和运行稳定。
- 与 demoparser2 的击杀和伤害数量交叉核对一致。

### 1.3 玩家过滤

CS2 Demo 的原始玩家记录不一定全部是参赛选手。当前清洗规则为：

1. 只保留 `terrorist` 和 `counter-terrorist` 阵营。
2. 排除 `DemoRecorder` 和 `spectator`。
3. 排除 `m_iCoachingTeam` 非零的教练。
4. 对名称以 `Coach|` 开头的记录进行兜底排除。

该规则在包含教练与旁观者的赛事 Demo 上验证后，保留了 10 名真实参赛玩家。

### 1.4 回合边界与赛后事件

少数事件出现在 `round.end_tick` 之后、下一回合开始之前。系统将此类事件归入上一回合并记录：

```text
payload_json.is_post_round = true
```

行为指标默认排除赛后事件；逐秒位置只保留回合有效时间内的采样。

### 1.5 完整比赛判定

- `has_match_end`：检测到 `cs_win_panel_match`。
- `regulation_complete`：检测到比赛结束，且任一方回合胜场达到 13。

投降、片段或缺少比赛结束事件的 Demo 可以用于兼容性测试，但不会被写成完整常规比赛样本。

## 2. 行为特征定义

### 2.1 开局路线与区域偏好

以冻结期结束为行动开始时间，取前 15 秒内首次进入的非出生区地点作为本回合首次区域，并记录前三个不同地点的顺序。

对于有显式区域映射的地图，可进一步得到 A、B、中路等区域。当前 7 张现有地图
均配置国内常用点位词典；A/B/中路等聚合区域表仍主要覆盖 `de_mirage`，其他地图
优先展示真实中文点位名。

### 2.2 队友距离

设玩家 \(p\) 在采样时刻 \(t\) 与同阵营存活队友集合为 \(T_t\)，最近队友距离为：

\[
d_p(t)=\min_{q\in T_t}\left\lVert pos_p(t)-pos_q(t)\right\rVert_2
\]

当前规则：

- \(d_p(t)\leq 500\)：靠近队友。
- \(d_p(t)>800\)：远端独立行动。
- 两者之间：过渡区间。

系统同时报告中位数、近队比例和远端比例。500/800 是初始工程阈值，不是游戏官方标准。

### 2.3 首轮交火与首杀

每回合第一条有效伤害事件涉及目标玩家，记为“参与首轮交火”。每回合第一条有效击杀由目标玩家完成，记为首杀；目标玩家为受害者时记为首死。

首轮交火参与率为：

\[
OCR=\frac{N_{first\ contact}}{N_{rounds\ with\ samples}}
\]

同一 tick 多事件可能无法唯一还原先后顺序，因此该指标保留顺序歧义说明。

### 2.4 支援行为

系统定位每回合队友首次参与伤害事件的时间，使用前后 2 秒内的采样估计目标玩家与该队友的距离。距离不超过 800 时记为“就近”。若玩家在接触后 5 秒内造成伤害或击杀，则记为“立即响应”。

该指标描述可观测距离与战斗参与，不等同于主观支援意识。

### 2.5 道具行为

- 购买事件用于统计道具购买意图。
- 烟雾、燃烧、闪光致盲和道具伤害事件用于统计可观察效果。
- 购买不等于实际投掷；完全无效的投掷可能无法从当前字段完整识别。

### 2.6 最后存活状态

逐秒采样中，目标玩家存活、本方仅剩其一人且至少一名敌人存活时，记录“最后存活状态”。当前只识别状态与结果，不推断主动或被动心理。

## 3. 可解释战术规则

当前规则版本为 `tactical-rules-v0.2`，主要模式包括：

- 首次进入地点和早期区域。
- 早期区域转移。
- 靠近队友、远端独立行动和过渡距离。
- 每回合首杀、首死和首轮交火。
- 队友接敌时就近响应或未立即响应。
- 可观察道具效果。
- 最后存活状态。

每个模式包含：

- 稳定规则键。
- 中文标签。
- 选择理由。
- 证据 ID。
- 规则完整度提示。
- 规则版本。

“置信度”是规则完整度提示，不是校准后的概率。

## 4. 关键回合排序

系统不直接把比赛胜负归因于单人，而是用可解释分数排序复盘候选。

正向分：

\[
S_+ = 0.8K + 0.4A + 2O_K + 0.4S + 0.5W + 0.3H
      + \min(0.15U, 0.45)
\]

其中：

- \(K\)：该回合击杀数。
- \(A\)：助攻数。
- \(O_K\)：是否取得首杀。
- \(S\)：是否存活到回合结束。
- \(W\)：队伍是否获胜。
- \(H\)：队友首次交战时是否就近。
- \(U\)：可观察道具效果数量。

问题复盘分：

\[
S_- = 2O_D + 0.6\max(D-K,0) + 0.4L
\]

其中：

- \(O_D\)：是否首死。
- \(D\)：死亡数。
- \(L\)：队伍是否输掉回合。

综合影响分为 \(S_+-S_-\)，用于排序高影响回合。系统分别展示优秀回合、高影响回合和优先复盘回合；评分不代表系统已确认玩家失误。

## 5. 证据约束报告

### 5.1 事实包

系统先生成固定结构 FactBundle，包括：

- 对局环境。
- 玩家身份。
- 指标定义、值、样本量和证据。
- 每回合行为与结果。
- 关键回合。
- 战术模式。
- 分析限制。

### 5.2 大模型输入

外部模型只接收去标识化事实包：

- 不发送 Demo 文件。
- 不发送玩家名称或 Steam ID。
- 不发送原始坐标。
- 只发送聚合指标、回合摘要、去标识化事件摘要和允许引用的证据 ID。

### 5.3 输出校验

模型输出必须是包含固定章节的 JSON。以下内容会被自动拒绝并回退模板：

- 缺少必需章节。
- 引用事实包之外的证据。
- 事实或行为推断没有证据。
- 引用不存在的回合。
- 声称读心或百分百还原想法。
- 非法 JSON。

### 5.4 模板降级

模板报告使用同一事实包生成六个部分，不依赖网络。它通过首轮交火、死亡地点、目标事件、支援距离、道具效果和回合结果组织回合叙事。

## 6. 系统实现

系统采用本地模块化单体：

- Awpy：Demo 解析。
- Polars/Pandas：数据处理。
- SQLite：事实存储。
- Python 规则：行为特征、战术模式和关键回合。
- Streamlit：页面。
- Plotly：地图、热力图和经济图。
- OpenAI-compatible HTTP Provider：可选大模型。

主要页面：

1. 上传或选择 Demo。
2. 选择主要分析玩家。
3. 全场画像和核心指标。
4. 地图路线与热力图。
5. 关键回合。
6. 单回合事件、模式、影响和备选方案。
7. 六部分报告与 Markdown 导出。

## 7. 初步实验

截至当前：

- 解析 19 个 CS2 Demo。
- 覆盖 7 张地图。
- 19/19 文件通过玩家数、双方阵容、位置、经济和核心事件检查。
- 190 条选手-对局记录，来自 114 名唯一选手。
- 6 场达到常规完整终局，覆盖 Ancient、Anubis、Dust2、Inferno、Mirage、Nuke。
- 完整终局包含 60 条选手-对局记录，来自 45 名唯一选手。
- 完整对局回合计为 179。

详细输出：

- `experiments/results/experiment_20261104T095547Z.json`
- `experiments/results/experiment_20261104T095547Z_summary.md`

这一阶段可以说明系统在多地图真实数据上的解析和指标执行能力，不能说明战术分类准确率。

## 8. 当前限制

- 完整比赛只有 6 场，且全部为职业赛事，与普通玩家存在分布差异。
- 尚无人工战术标签。
- 规则阈值需要更多样本和人工案例分析。
- 地图区域语义目前主要覆盖 Mirage。
- 投掷物行为仍不能完整识别所有零效果投掷。
- DeepSeek 真实 API 和证据校验链路已经执行；不同模型的横向对比尚未完成。
- 学校模板、截止时间与导师算法要求尚未取得。
