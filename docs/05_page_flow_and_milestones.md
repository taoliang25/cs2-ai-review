# 页面流程、MVP 与开发里程碑

- 文档版本：v0.1
- 更新日期：2026-11-04
- 默认运行方式：本地 Streamlit

## 1. 页面信息架构

### P1：上传与解析

目标：让用户清楚知道文件是否可用。

元素：

- Demo 上传框或本地路径输入。
- 文件格式、大小和 SHA-256 提示。
- 上传与解析状态。
- 地图、模式、回合数和玩家数量摘要。
- 解析失败原因及可操作建议。

限制：

- 只接受单场 `.dem`。
- 先检查常规 5v5 条件。
- 不在此页显示虚假报告占位内容。

### P2：玩家选择

目标：以稳定身份选择一个主要分析玩家。

元素：

- 按阵营分组展示真实玩家。
- 显示玩家名、Steam ID 后几位、阵营。
- 单选并明确确认。
- 可选显示本场基础统计作为识别辅助。

过滤：

- 排除 `DemoRecorder`、旁观者及其他 `side` 为空的记录。

### P3：全场总览

目标：先给结论，再提供证据。

模块：

- 对局摘要：地图、比分、回合数、阵营。
- 玩家画像：风格、优势、坏习惯和主要问题。
- 核心指标卡片：开场路线倾向、跟队倾向、首杀尝试、道具使用、残局和支援。
- 全场位置热力图与常用路线。
- 经济变化与回合结果。
- 最重要的三个问题和训练建议。
- AI 报告状态：大模型或模板。

### P4：关键回合列表

目标：让用户从全场结论下钻。

元素：

- 优秀回合、问题回合、高影响回合、代表性回合分类。
- 回合比分、阵营、经济、结果和入选理由。
- 关键事件的简短时间线。
- 证据数量和完整性。

### P5：单回合详情

目标：解释发生了什么、造成什么影响、还能考虑什么。

元素：

- 回合背景：比分、经济、阵营和人数。
- 轨迹地图和时间轴联动。
- 投掷物、击杀、伤害、炸弹及首杀等事件。
- 可观测影响。
- 行为推断与不确定性说明。
- 当时可选方案和建议，明确标为复盘意见。
- 本回合证据列表。

### P6：报告与导出

首版可选：

- 浏览器内查看报告。
- 导出 Markdown。
- PDF/Word 导出需按学校要求确定，不在未确认格式前投入大量时间。

## 2. 页面状态机

```text
WAITING_UPLOAD
  -> PARSING
  -> PARSE_FAILED
  -> WAITING_PLAYER_SELECTION
  -> ANALYZING
  -> ANALYSIS_FAILED
  -> REPORT_READY
  -> ROUND_DETAIL
```

每个失败状态必须保留可理解的错误代码和下一步建议。

## 3. 最小可行版本

### 3.1 MVP 必须完成

1. 上传并解析一场真实、完整的常规 5v5 Demo。
2. 从解析结果展示真实玩家列表并选择一名玩家。
3. 保存回合、关键事件、逐秒位置和回合经济。
4. 计算首批可解释指标：
   - 开局活动和路线。
   - 跟队/分离。
   - 首次交战和首杀尝试。
   - 道具类型、使用时机和落点。
   - 优势/劣势回合差异。
   - 残局处理。
   - 队友交战时的支援距离和到达情况。
5. 推荐至少一个优秀回合和一个问题回合。
6. 展示位置图、热力图、经济变化和关键事件。
7. 生成包含六个已确认模块的模板报告。
8. 可选接入大模型，并支持无 API 降级。
9. 本地一键启动和演示数据自检。

### 3.2 MVP 可以后置

- 公网部署。
- 用户账号。
- 多场历史列表。
- 多人同时分析。
- 实时比赛接入。
- 复杂动作识别模型。
- 自动视频剪辑。
- 商业化界面和权限系统。

### 3.3 MVP 演示验收脚本

1. 打开首页。
2. 上传预先验证过的 Demo。
3. 展示地图和 10 名真实玩家。
4. 选择目标玩家。
5. 生成全场画像。
6. 打开位置热力图并切换到关键回合。
7. 查看一个优秀回合和一个问题回合。
8. 点击事件证据，能定位到对应回合和时间。
9. 断开 API 后重新生成，模板报告仍可展示。
10. 查看数据来源和解析版本。

## 4. 开发里程碑

时间是相对安排，未计入学校模板适配和答辩等待，必须在截止时间确定后重排。

| 里程碑 | 目标 | 主要产物 | 建议周期 |
|---|---|---|---:|
| M0 可行性验证 | 解析器、环境、样本和字段验证 | 验证报告、环境脚本 | 已完成主体 |
| M1 事实层 | 单 Demo 导入 SQLite，过滤玩家并保存事件/位置 | 解析 CLI、数据库、自动化检查 | 3-5 天 |
| M2 特征与关键回合 | 首批指标、规则版本、关键回合排序 | 指标模块、事实包样例 | 5-7 天 |
| M3 本地网页 MVP | 上传、选人、总览、回合详情 | Streamlit 可运行版本 | 7-10 天 |
| M4 证据可视化 | 雷达图、热力图、时间线、经济图 | 可交互图表 | 4-6 天 |
| M5 智能报告 | Provider、提示词约束、输出校验和降级 | 模板/API 报告闭环 | 4-6 天 |
| M6 实验与真实验证 | 多场 Demo、规则检查、模型评估（如采用） | 实验记录、表格、图 | 7-12 天 |
| M7 论文与答辩 | 系统说明、算法、实验、截图、演示稿 | 论文材料、答辩版本 | 7-10 天 |

### 4.1 关键路径

```text
真实完整 Demo
  -> 事实层
  -> 指标口径
  -> 关键回合
  -> 网页闭环
  -> 报告事实约束
  -> 实验与论文
```

任何新增功能都不得阻断这条关键路径。

## 5. 每个里程碑的验收

### M1

- 同一 Demo 多次导入结果一致。
- 过滤观战者后恰好为真实 5v5 玩家。
- 回合、击杀、伤害、经济与位置可查询。

### M2

- 每个指标有定义、公式或规则说明。
- 每个结论能追溯到证据 ID。
- 样本不足时显示缺失，而不是补写。

### M3

- 用户能完成上传到单回合详情的完整操作。
- 刷新页面不会丢失已完成的分析。
- 错误状态可解释。

### M4

- 雷达坐标抽查正确。
- 热力图不是装饰性散点图，能反映真实采样密度。
- 事件图与时间线能够相互定位。

### M5

- 无 API 可完整生成报告。
- API 输出不能引用不存在的事件。
- 报告明确区分事实、推断和建议。

### M6

- 所有数字来自真实运行。
- 训练/验证/测试划分按 Demo 分组。
- 论文能解释标签来源、泄漏风险和评价局限。

### M7

- 本地演示从启动到报告完成可重复。
- 答辩时能在 5-8 分钟内讲清数据、算法、系统和局限。

## 6. 首轮开发顺序

1. 建立 Awpy 数据适配器和事实层。
2. 用当前测试 Demo 生成 SQLite。
3. 实现玩家过滤和回合关联。
4. 先做一个选手的开局路线、跟队/首杀指标。
5. 做开场热力图和回合时间线。
6. 再做关键回合选择。
7. 最后接模板报告和大模型。
